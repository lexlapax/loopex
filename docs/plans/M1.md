## Normative Concept Envelope

<a id="concept-plan-purpose"></a>
### Purpose

Make Loopex usable. One process starts the runtime, creates or resumes a durable
session, sends a real prompt to a real model, runs one controlled local tool, and
observes committed events through an embedded API — then survives a kill and
continues without duplicating an effect or losing durable truth.

M0 proved the semantics hold in disposable code. This milestone turns the proved
semantics into a local kernel someone can run, and claims nothing beyond one
machine and one attached caller.

| 2 | A session is created or resumed through the embedded API, and its durable truth is owned by exactly one coordinator for the session's life | Property and fault injection | `mix test apps/loopex/test/session_lifecycle_test.exs` |

<a id="concept-plan-scope"></a>
### Scope

Product code intended to survive. One machine, one attached caller, one session
at a time per coordinator, with a durable store behind a port and a controlled
local executor.

Reuse from M0 is deliberate and per module rather than wholesale: the session
reducer, the effect admission rules, and the model adapter carry forward on their
proved semantics; the journal moves behind the store port; the coordinator keeps
its guarantees while its startup shape changes to suit an explicit runtime.

<a id="concept-plan-non-goals"></a>
### Non-Goals

Multi-client attachment and a protocol candidate, a daemon or network transport,
distribution across nodes, isolated or remote hands, an extension manifest or
activation claim, publication of any package, and any public compatibility claim.

Multi-client attachment is the next serial barrier and is deliberately excluded.
Combining it with this milestone would produce a second long foundational
milestone before anything is usable, which is the failure this scope exists to
avoid.

VM code generation stays a spike. M0 claimed nothing about quiescent activation,
atomic module-set loading, or exact rollback, and this milestone does not promote
that spike to a production extension runtime.

Nothing here is a general-purpose framework surface. A checker, registry, or
document that does not serve the working loop belongs to a later milestone.

## Workstreams

Ownership, rejoin barriers, and the serial constraint between them are in the
[technical envelope](M1-technical.md#technical-plan-ownership).

- **A — Runtime and lifecycle.** Outcomes 1, 2. Blocks every other workstream.
- **B — Durable store.** Outcome 3. The milestone's constitutional core, and the
  home of the owner-epoch fencing M0 deferred.
- **C — Boundaries.** Outcomes 4, 5, 6. Embedded API, model port, executor.
- **D — Demonstration.** Outcomes 7, 8. Rejoins last and proves the whole loop.
