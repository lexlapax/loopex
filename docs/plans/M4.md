## Normative Concept Envelope

<a id="concept-plan-purpose"></a>
### Purpose

Let an independent program use the local skills and core repairs M3 proves, then
add durable policy questions and bounded artifact retrieval. Select an
admitted skill, drive a coding session, answer a durable policy question,
observe progress and committed results, retrieve an artifact, and recover the
same durable session after process loss. Ship one foreground stdio JSONL server
and a useful independent consumer over the public facade. Complete M4 as an
operator-usable, source-only `0.1.0` release: from the exact source candidate,
an operator follows the documented setup and drives that workflow with their
own inputs before the reviewed integrated closure is tagged `v0.1.0`.

M4 first implements durable interactions in core and bounded retrieval at the
ArtifactStore/facade boundary, then adds an external consumer, schemas and
delivery mechanics. It reuses M3 resource admission, operator selection, launch
configuration and recovery. The protocol never owns a second policy engine or
resource resolver. The floor refresh supports its standard-library JSON codec.
Keeping this milestone separate lets M3 deliver skills without those protocol
prerequisites; M4 proves its new shared contracts locally before wire mapping.

<a id="concept-plan-scope"></a>
### Scope

The server owns framing, connection-local correlation, delivery pressure and
foreground process lifetime. Core owns durable session truth. Hosts supply
workspace, identity, policy, provider configuration and project resources at launch;
client requests cannot choose modules, grant profiles, roots or credentials.

Initialization precedes mutation. Request identity is ephemeral correlation;
command identity provides durable idempotency; interaction identity survives
transport loss. Creation does not silently attach. Attach returns the unchanged
revision-2 snapshot, cursor and same-cursor open-interaction view before live
delivery. Command admission is distinct from completion,
and progress is distinct from committed events. Lost progress falls back to
snapshot/event truth. Artifact references stay opaque and retain separate
object/use identity.

Closed M3 proves settled-state behavior but does not emit the separate public
`session.settled` fact required by accepted ADR 0011. M4 completes that
existing contract in core before projecting the event through the wire; it
does not claim the event was already inherited.

This generation does not list sessions through the wire. The consumer retains
the ID returned at creation, shows it to the operator, and can take that ID
again for a later resume. The host fixes project-resource trust at launch;
clients may inspect and select admitted resources but cannot issue a live
project-trust decision. The maintainer approved both exclusions during M4
acceptance preparation on 2026-09-13.

Observability is the first workstream. A runtime may own one isolated OTP
trace session over its own processes and an allowlist of Loopex modules,
reporting function identity, caller, process and timing for every call with no
instrumentation in the traced source; argument and return capture is an
administrative opt-in and is always bounded and redacted: at most 4,096 bytes
per entry after redaction, at most 2,000 entries per second per session and at
most 8,192 queued entries, with every excess dropped and counted. Core emits
`:telemetry` spans at every port callback and coordinator transaction cut in a
bound inventory, with identities, kinds, outcome categories, durations and
counts, never content or credentials. Telemetry emission is synchronous by the
library's design, so core attaches no handler; the `loopex_telemetry` edge
owns the only Loopex-attached handler, which hands events to the diagnostics
dispatcher's asynchronous admission path. That dispatcher owns bounded
admission for the queues Loopex controls: a sender claims one of 4,096 slots
with a single atomic insert that records it as the owner before sending, so
the admission backlog never exceeds 4,096 items per runtime however many
senders race; drops are counted without a send and summarized exactly by one
atomic exchange; the slots a dead sender claimed and never sent for are
released when its monitor reports it dead, whichever step it died at, and a
live claim is never touched; and the host sink's own mailbox is backpressured,
never claimed as bounded. ADR 0030 supersedes only
the two ADR 0001 clauses that required an empty core dependency list. Host-attached handlers run in the emitting process and are the host's
responsibility. Nothing here is authority: no session command, client
content, model output, project resource or wire request can start, change or
stop tracing. `:telemetry` is core's sole external dependency under the
recorded vision change; reporters and OpenTelemetry stay at the edge. Trace
sessions need the refreshed OTP floor; on an older release the facility is
unavailable evidence, never a fallback to VM-global tracing.

Hosts fix the launch inputs before the first frame: state root, workspace
identity, resource snapshot, policy module with its identity and revision,
provider, executor and ArtifactStore. No wire content replaces any of them.
An interaction answer is evidence for a new host-policy decision; it is never
an approval or a grant. Each tool decision admits a bounded number of
successive answer → defer rounds: this candidate permits two after the first
question, hence at most three questions per tool decision, as accepted ADR 0024
fixes.

Saving a complete artifact costs one complete verification per authorized
transfer, never one per chunk. The opening verification's deadline and work
budget, chunk bytes, per-read deadline, open-transfer lifetime, concurrent
transfers, connection work and that amplification bound are exact, named in
the technical envelope and bound at acceptance with the accepted ADR 0028.
The proposed transfer profile caps objects at 64 MiB, opening at 60 seconds
and 128 MiB of work, chunks at 32 KiB and five seconds per read, lifetime at
ten minutes, concurrency at two per connection/four per runtime, and
connection work at 1 GiB with a 1 MiB minimum debit per open.

The independent example is a small usable consumer, not a fixture. It reads
operator choices and interaction answers from its own input, lists the admitted
catalog, explicitly selects a skill, submits a task, presents the exact pending
interaction, follows the resulting tool execution, saves a bounded artifact
stream and resumes after abrupt server loss; it embeds no session, interaction
or answer identity. Three endings are distinct everywhere. Clean stdin EOF is
the host closing the connection: the server performs the inherited orderly
foreground shutdown, records no cancellation and changes no interaction state.
Abrupt process death records nothing; the journal alone says what settled and
the inherited recovery contract resolves the rest. Only the durable
`session.abort` command cancels. In the first two cases a pending interaction
stays pending after restart; each case is proved separately.

All new surfaces remain experimental, with exact schema/generation agreement
and no mixed-generation promise. M4 adds versioned core interaction records;
new readers replay M3 histories and old readers refuse new records before effects.
Rollback retains the old root/binary pair, not just an older server executable.
The accepted floor refresh still requires every affected holder transaction,
including M3, before M4 binds it. The release is one
annotated `v0.1.0` tag on the exact integration commit on `main` that contains
the independently reviewed closure transition, and a source archive of that
tagged commit. The full gate first retains a report for a staged candidate
archive and runs the attended workflow from its fresh extraction. After
integration, release verification binds the tag, commit, tree, archive digest
and `VERSION`; it does not relabel the earlier candidate proof. The release
publishes no Hex package, binary, installer or service and
freezes no public protocol or embedded API. Tag creation and publication follow
closure review and explicit release authority; neither is implied by a green
gate alone.

<a id="concept-plan-non-goals"></a>
### Non-Goals

No second resource manager, policy engine, interaction reducer or session loop.
No daemon, sockets, persistent concurrent-client residency, controller takeover,
trusted extension activation, marketplace, hosted skill API, mid-session model
switch, ACP mapping, protocol freeze, Hex package, binary or installer. Those later
capabilities retain their vision barriers and require their own evidence.

those repaired gates, and the M4 full lane to its declared opening red. Each

workstream lands, M4 carries no inherited-green claim, `mix loopex.matrix`
stays red, and any M1 or M2 regression under the new floor is unobserved;
M4 closure cannot proceed before it lands.

Settle floor/holder transactions and DTO/core contracts against M3's actual
facade. Land observability first, because every later workstream is debugged

means enabling a runtime trace session and reading telemetry events, not ad
hoc printing, and keep that guidance current through closure. Prove core interaction and ArtifactStore transfer
paths, then join a thin server/client workflow before method breadth. Reuse M3's focused checkpoints,
clause witnesses and integrated self-audit; full inherited checks remain at
