## Normative Concept Envelope

<a id="concept-plan-purpose"></a>
### Purpose

Prove, in disposable code, that durable session truth, honest effect recovery,
and VM-global trusted-code evolution are feasible under the intended OTP
semantics, and stand the repository's own validation on the accepted Elixir
toolchain.

<a id="concept-plan-outcomes"></a>
### Outcomes

| # | Outcome | Evidence class | Gate selector |
| --- | --- | --- | --- |
| 1 | An umbrella scaffold exists with a contract application carrying no dependencies and a runtime application whose only dependency is the contract | Structural check | `mix loopex.deps_budget` |
| 2 | A repository-owned dependency-budget and direction command rejects a forbidden dependency, a reverse edge, and a dynamic reference, and the client hook calls it rather than duplicating it | Adversarial corpus | `mix test apps/loopex/test/deps_budget_test.exs` |
| 3 | The running toolchain matches a locked pair, and both locked pairs are recorded as run | Per-pair matrix evidence | `mix loopex.matrix` |
| 4 | A session journal survives a restart: replay reconstructs the same durable state | Property, fault injection, and a negative demonstration | `mix test apps/loopex/test/journal_replay_test.exs` |
| 5 | An effect committed with an unknown outcome is fenced, never blindly retried, and reconciled across a coordinator restart | Property, fault injection, and a negative demonstration | `mix test apps/loopex/test/fencing_test.exs` |
| 6 | Loading and rolling back a trusted code generation in an isolated VM is demonstrated, claiming nothing about extension activation | Demonstration and a negative demonstration | `mix test apps/loopex/test/vm_code_spike_test.exs` |

<a id="concept-plan-scope"></a>
### Scope

Disposable experimental product code, the first scaffold, the accepted toolchain
matrix, and the migration of repository validation onto that toolchain. Outcomes
4 through 6 are feasibility experiments: they answer whether the intended
semantics hold, and their code may be discarded at closure.

No product surface becomes public. Nothing in this milestone is released,
published, installable, or labelled stable, release-candidate, or experimental
as a public contract. Observable behavior is limited to repository commands and
retained evidence.

<a id="concept-plan-non-goals"></a>
### Non-Goals

Multi-client attachment, a daemon or transport, a durable store selection, an
extension manifest or activation claim, isolated or remote hands, tool
execution, publication of any package, and any compatibility claim.

Outcome 6 is a feasibility spike only. It does not claim quiescent activation,
atomic module-set loading, or exact rollback as governed capabilities; those
belong to a later milestone with its own evidence.

Distribution and multi-node operation are excluded. The vision's serial barriers
require local durable truth before any multi-node claim, so operation truth is
proved across a restart rather than across nodes.

## Workstreams

Ownership, rejoin barriers, and the serial constraint between them are in the
[technical envelope](M0-technical.md#technical-plan-ownership).

- **A — Foundation.** Outcomes 1, 2, 3, 9. Blocks every other workstream.
- **B — Durable truth.** Outcomes 4, 5. The milestone's constitutional core.
- **C — Code evolution.** Outcome 6.
- **D — Model boundary.** Outcome 7, in the adapter application.
- **E — Self-hosting.** Outcomes 8, 10. Runs in parallel with B, C, and D after A
  rejoins, and may not consume their review attention.
