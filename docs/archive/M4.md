## Normative Concept Envelope

<a id="concept-plan-purpose"></a>
### Purpose

Let an independent program use the local foundations M3 proves: select an
admitted skill, drive a coding session, answer a durable policy question,
observe progress and committed results, retrieve an artifact, and recover the
same durable session after process loss. Ship one foreground stdio JSONL server
and a useful TypeScript consumer over the public facade.

M4 adds an external consumer, schemas and delivery mechanics. Resource
acquisition/admission, skill selection, interaction authority, artifact identity
and session recovery have one implementation inherited from M3. A defect in
those foundations is repaired at its owner rather than worked around at the
wire. Keeping this milestone separate gives the external boundary a focused
acceptance gate after the local workflow is real.

<a id="concept-plan-scope"></a>
### Scope and Observable Constraints

The server owns framing, connection-local correlation, delivery pressure and
foreground process lifetime. Core owns durable session truth. Hosts supply
workspace, identity, policy, provider configuration and source roots at launch;
client requests cannot choose modules, grant profiles, roots or credentials.

Initialization precedes mutation. Request identity is ephemeral correlation;
command identity provides durable idempotency; interaction identity survives
transport loss. Creation does not silently attach. Attach returns a snapshot
and cursor before live delivery. Command admission is distinct from completion,
and progress is distinct from committed events. Lost progress falls back to
snapshot/event truth. Artifact references stay opaque and retain separate
object/use identity.

The TypeScript example is a small usable consumer, not just an echo/vector
fixture. It lists the admitted catalog, explicitly selects a skill, submits a
task, presents and answers an interaction, follows the resulting tool execution,
saves a bounded artifact stream and resumes after abrupt server loss. A second
workflow tests graceful EOF/cancellation separately so a cancelled interaction
is never falsely described as recoverable pending work.

<a id="concept-plan-non-goals"></a>
### Non-Goals

No second resource manager, policy engine, interaction reducer or session loop.
No daemon, sockets, persistent concurrent-client residency, controller takeover,
trusted extension activation, marketplace, hosted skill API, mid-session model
switch, ACP mapping, protocol freeze or implicit publication. Those later
capabilities retain their vision barriers and require their own evidence.
